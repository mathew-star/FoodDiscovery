## Claude Code specifics

- Plan before multi-file changes; state the spec story IDs the change covers.
- Before touching a Next.js API, read the matching guide in `node_modules/next/dist/docs/` (install deps first if missing).
- Verify with commands, not file dumps: `bunx next typegen && bunx tsc --noEmit`, `bun run lint`, tests. Report failures with their output.
- Prefer `Edit` diffs over full rewrites; do not re-read files already in context.
- Never print or ask for `.env` values. Network calls to Neon/Upstash/R2/Resend need the user's local env; say so instead of guessing.
- Do not commit the Next.js managed block out of `AGENTS.md`; it is regenerated by `next dev`.
- End of a phase: tick `docs/PROGRESS.md`, add any new decision to `docs/ARCHITECTURE.md` §Decisions.
- Cloud sessions push only to the branch named by the session; open PRs only when asked.
